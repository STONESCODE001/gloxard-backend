Introduction

Welcome to the Gloxad REST API documentation. This API powers secure student and instructor authentication, account onboarding, role authorization, and password recovery workflows.

All requests accept standard JSON payloads with Content-Type: application/json. Every response returns JSON with consistent error envelopes formatted as { "error": "<message>" }.

Base URL & Server

All API requests must be directed to the live Render deployment endpoint below.

Production Base URL (Render)
https://gloxard-backend.onrender.com/api

For local development when running via npm run dev, the API is available at http://localhost:3001/api.

Authentication

Protected endpoints require a signed JSON Web Token (JWT) provided in the HTTP Authorization header using the standard Bearer scheme:

HTTP Header 
Authorization: Bearer <your_jwt_access_token>

Obtain this token by authenticating with your credentials via POST /api/auth/signin. Tokens remain valid for 7 days.

HTTP Status Codes

The Gloxad API returns conventional HTTP response codes to indicate the success or failure of requests. Below is the complete catalog of status codes used across all endpoints:

Status Name Meaning When Returned
200 OK Standard response for successful HTTP requests. Successful login, profile retrieval (/me), OTP pre-check, and password resets.
201 Created Request fulfilled and resulted in a new resource being created. Successful user registration (POST /api/auth/signup).
400 Bad Request Server cannot process request due to client error or missing required fields. Missing email/password, malformed input, invalid OTP, or expired OTP.
401 Unauthorized Request lacks valid authentication credentials. Missing, expired, or malformed Bearer token on protected endpoints, or invalid login credentials.
403 Forbidden Server understands request but refuses to authorize access. Attempting access without verified role or with pending instructor approval.
404 Not Found The requested endpoint or resource does not exist. User account not found, or invalid URL path.
409 Conflict Request cannot be completed due to a conflict with existing state. Attempting to register with an email that is already in use.
422 Unprocessable Entity Request body is syntactically correct but semantically invalid. Weak password that fails validation criteria, or invalid email format.
429 Too Many Requests Client has sent too many requests in a given amount of time (rate limit). Exceeding rate limit windows on authentication attempts or OTP verification dispatches.
500 Internal Server Error Server encountered an unexpected condition that prevented request fulfillment. Unexpected database errors, SMTP dispatch failures, or unhandled server exceptions.

Standard Error Response Format

All 4xx and 5xx responses strictly adhere to the unified error envelope structure:

JSON Error Envelope 
{
  "error": "Detailed explanation of the error condition"
}

Initiates password recovery by dispatching a 5-digit numeric OTP with a 15-minute expiration to the user's email. Features anti-enumeration security.

}
Response 200 OK 
{

5. Course Taxonomy & Category Management

Hierarchical course classification system allowing public retrieval of categories, subcategories, and topics, with administrative-only CRUD operations restricted to users with role === 'admin'.

GET /api/categories Public (No Token Required)
Returns the complete hierarchical taxonomy tree of all course categories, subcategories, and topics sorted by display order.
Request Headers 
GET /api/categories HTTP/1.1
Host: localhost:3001
Accept: application/json

          "topics": ["React", "Node.js", "TypeScript"]
        }
      ]
    }
  ]
}

Creates a new top-level category document with optional subcategories and topics. Requires administrative privileges.

8. Real-Time Messaging & In-App Notifications (REST + Socket.io)

Real-time messaging engine, in-app notification management system, REST API endpoints (/api/messages/* and /api/notifications/*), and Socket.io WebSocket server with JWT handshake authentication. Supports 1:1 and group course conversations, live message delivery, typing indicators, user room push notifications.

WS Event Socket.io WebSocket Real-Time Events JWT Auth Handshake
Socket.io handshake authentication requires auth: { token: "<jwt_access_token>" }. Clients automatically join room user:<userId> on connection.
Event Name Direction Payload Shape Description
join_user Client → Server { "userId": "..." } Automatically called on connection; joins room user:<userId>.
join_conversation Client → Server { "conversationId": "..." } Client joins conversation room conv:<conversationId>. Validates membership.
leave_conversation Client → Server { "conversationId": "..." } Client leaves conversation room conv:<conversationId>.
typing Client → Server { "conversationId": "..." } Broadcasts typing event to room conv:<conversationId> excluding sender.
stop_typing Client → Server { "conversationId": "..." } Broadcasts stop_typing event to room conv:<conversationId> excluding sender.
new_message Server → Client Message object payload Emitted to room conv:<conversationId> when a message is posted.
new_notification Server → Client Notification object payload Emitted to room user:<recipientId> when a notification is generated.
